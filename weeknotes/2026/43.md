## Timeseries processing pipeline

Lots of minor improvements have been made to the processing pipeline to help processing speed, introduce historic processing modes, and general bug fixes:

- A `historic` mode now processes every dataset for each site, dynamically finding it's start date and processing through to "today", chunking processing runs into one calendar year at a time.
- Flag columns are now named and typed from the dataset metadata, so datasets no longer need a core flag column. Every saved dataset gets all the flag columns its metadata declares.
- Methods now get their input datasets by name from the metadata, rather than assumptions being made about dataset dependencies
- Derivation calculations have moved into the `hydrometlib` package (see below).
- Fixed some flagging issues, so values removed by QC are marked as removed, and corrected values keep their corrected flag.
- Loading data from S3 is much faster, after improvements made to the DuckDb querying. The main win was to first build the list of parquet files being queried to pass to DuckDb, so that DuckDb didn't have to open _all_ parquet files in a glob to determine the data schema.

## New open source python libraries: Hydrometlib and Isoperiod

- **[Hydrometlib](https://nerc-ceh.github.io/hydrometlib/)**: A Python library for verified and referenced hydrometeorological calculations and derivations.
  - This makes all the derivation calculations used in our processing pipeline fully open and usable by the community
- **[Isoperiod](https://nerc-ceh.github.io/isoperiod/)**: A Python library for working with ISO 8601 periods: the repeating intervals that give timeseries data its sampling resolution and periodicity.
  - This was previously a hidden module within [Time-Stream](https://nerc-ceh.github.io/time-stream/), but we have extracted it into its own library as it may be more generally usable for the wider community

## Network Monitoring

### Battery trend

We are adding trend analysis to the most recent minimum overnight battery voltages to spot those that are heading towards their minimum voltage threshold.  This will show when batteries are at risk of running out of sufficient power, which is becoming more important now the solar panels are heading towards short winter days.

### Completeness of live data

A new feature being added is live gap detection across all variables for a site's raw data.  This is so field engineers can spot problems early, even before the data has been processed.  All variables are shown together in a mosaic regardless of their temporal resolution.  They can be sorted and filtered to examine any patterns in the gaps that may indicate a sensor issue or simply show that no data at all is coming in.  Data for the last 24 hours is displayed, with the ability to step back through previous days.  Each variable can be shown on a simple chart with gaps highlighted.  The example below shows Cockle Park on the COSMOS-UK network, where something seems to have caused a set of variables to miss some values during the last 24 hours:

### Quality Control flags

We have been looking at how to display Quality Control flags in the dashboard.  The great work to display flags in the Timeseries UI (see Public UI elsewhere in this Weeknotes) means that all flag data is made available by the backend API.  Early prototypes have used the API data to produce a whole site view of variable flags, similar to the completeness above and the Public UI flag display - but with an additional table allowing filtering by different flag types to find what has been applied to which variable.  Once this has been refined it will be possible to link back to the Timeseries Explorer chart to examine in more detail and against other data.
